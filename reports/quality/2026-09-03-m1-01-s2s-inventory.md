# M1-01 — Speech-to-speech surface inventory

Status: accepted.

The repository contains 96 classified S2S surfaces. The inventory is deliberately broader than
four obvious backend files: it covers every execution branch, persisted value, Studio control,
dependency, event name, test, operational document, developer skill, frozen report, and exploratory
probe found by the versioned detector.

## Execution and persisted state

The two direct audio backends are `ChatGPTRealtimePipeline` (WebRTC) and
`OpenAIRealtimeWebSocketPipeline` (server WebSocket). They depend on ChatGPT OAuth and Gizmo
management and are selected through nine branches in `PhoneVoiceAgent`, including preloading,
preconnect, start, callback, recovery, and close behavior.

The migration contract records 18 legacy keys: `PHONE_AGENT_PIPELINE_MODE`, the forbidden
`s2s_chatgpt_realtime` value, fourteen `PHONE_AGENT_CHATGPT_*` controls, and two token inputs. Five
stores can retain legacy state: Studio JSON, control-plane revisions, ChatGPT session cache, Gizmo
cache, and the legacy local session cache. M1-04 and M1-05 therefore require both schema removal and
secret/data migration; deleting source fields alone would leave stale installations ambiguous.

Direct dependency bindings are explicit:

- `aiortc` and `curl-cffi` have no surviving Cascade import and are removal candidates;
- direct `av` ownership must be removed only after the Pipecat/transitive graph is proven;
- `websockets` remains temporarily owned by the current identity evaluator, which M1-08 must make
  provider-neutral before deciding whether the package survives.

## Events and behavior that cannot be lost

The inventory separates 23 provider-protocol event names, which die with the adapters, from 24
platform event names that need Cascade-neutral ownership. The latter include transcript delivery,
call completion/error, caller audio quality, tool lifecycle/reload, reconnect notices, and latency.

M1-02 must prove ten shared behaviors through Cascade before deletion: opening, authoritative
transcript, tools, interruption, end-call, recovery, evaluation, memory, call state, and verified
Android playout. This directly prevents a code-size cleanup from silently removing working GSM
behavior.

## Enforcement and verification

`ci/validate_s2s_inventory.py` scans file names and text, requires every detected path to have one
owner and disposition, validates the configuration/dependency/persistence/branch/event/behavior
maps, and fails on new unclassified surfaces or stale entries. It is part of the quality stage.

The final gate reports 902 passed, 40 skipped, and four device tests deselected in 53.74 seconds.
Ruff, strict Pyright, package, dependency-security, and licence/SBOM stages pass. No live runtime,
configuration, call, or phone state was changed; the connected worker remains ready on Cascade.
